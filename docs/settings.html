Settings

Every setting of [settings], with its default and what it does. This page is generated from ronin's built-in configuration (the text C-c , writes into a new ronin.conf), so it says what the program does. git_path and ai_command are shown only in examples: they are empty unless set. Where the file is and how it is applied: Configuration.

font

Font family: a monospace font installed on the system. If it is missing, Consolas is used.

font = Consolas

font_size

Font size in points, 4 to 96; decimals are allowed (10.5). The monitor's scale applies on top. C-x C-+ and C-x C-- change it for the session only, C-x C-0 goes back to this value.

font_size = 12

line_height

Line height in percent of the font's natural line height, 80 to 300.

line_height = 100

render_mode

Glyph rendering (ClearType): symmetric, natural or classic (GDI-like, crisper, narrower).

render_mode = symmetric

tab_width

Columns per tab stop, 1 to 16.

tab_width = 4

indent_width

Indentation: columns per level (1 to 16); with tabs or spaces; and whether a loaded file decides tabs or spaces for its buffer from its first indented lines. RET indents the new line, TAB reindents the line (or the region), a closing ) ] } typed first on a line reindents it. The rule: the previous non-blank line's indentation, plus its brackets opened minus closed, minus the closing brackets that start the line.

indent_width = 4
indent_with_tabs = false
detect_indentation = true

underscore_is_word

true: '_' is part of a word for M-f / M-b. false: it separates words (Emacs' C mode).

underscore_is_word = false

fsync_on_save

true: saving returns only once the file is on the disk (FlushFileBuffers). false: faster, but a power failure right after saving can lose the file.

fsync_on_save = true

undo_limit_mb

Undo history kept per buffer, in megabytes (1 to 2048). The oldest changes are dropped first; the last command can always be undone.

undo_limit_mb = 64

transient_mark_mode

true: the region (between point and mark) is highlighted while the mark is active, and region commands act on it only then (Emacs' transient-mark-mode). Shift with a motion key selects.

transient_mark_mode = true

delete_selection_mode

true: typing (or yanking) with an active region replaces it. false (Emacs' default): typing inserts at point; DEL and C-d still delete an active region.

delete_selection_mode = false

kill_ring_max

Kills (C-w, C-k, M-d, ...) kept for yanking (C-y, then M-y for older ones), 1 to 1000. Every kill also goes to the Windows clipboard, and C-y takes the clipboard when another program changed it since.

kill_ring_max = 60

completion_lines

Rows of the candidate list above the minibuffer (M-x, C-x C-f, C-x b ...), 1 to 40.

completion_lines = 8

auto_revert

true: a buffer without unsaved changes whose file changed on disk is reloaded (when ronin is activated, and at once for the buffers on screen). A buffer with unsaved changes is never touched, only flagged in the mode line. false: unchanged buffers are flagged too.

auto_revert = true

show_paren_mode

true: the bracket at point (or the closing one just before point) and its match get the paren_match background. Brackets in comments and strings have no match.

show_paren_mode = true

split_width_threshold

Windows (C-x 2, C-x 3, C-x o, ...). A command that shows a buffer in another window (C-x 4 b, C-x 4 f, C-h e) splits a single window side by side when the frame is at least this many columns wide, otherwise one above the other.

split_width_threshold = 160

startup_windows

Windows at startup: 1, or 2 (side by side; the second shows the second file on the command line).

startup_windows = 1

early_window

true: at startup the window is shown at once, in the background color, and the first frame replaces it when the graphics device is ready (~150 ms later). false: it appears with the first frame. Read once, at startup.

early_window = false

project_markers

Projects: C-x p f finds a file in the current project by fuzzy matching its path. The root is the nearest directory above the buffer's file that holds one of these markers (files or directories, blank-separated). Without one, only a directory given on the command line (ronin <directory>) is a project, for the files inside it and for *scratch*. A .ronin-project file at the root can list [ignore] and [allow] patterns, one per line.

project_markers = .git .hg .svn .ronin-project

project_ignore

Never listed in a project, in .gitignore syntax, blank-separated (the project's .gitignore files apply too). Only names that cannot be source directories: a name pattern matches at any depth, so build/, out/, bin/ or obj/ here would also hide a real source directory of that name. Put those in the project's .gitignore or .ronin-project instead.

project_ignore = .git/ .hg/ .svn/ .vs/ node_modules/ __pycache__/ *.exe *.dll *.lib *.obj *.o *.a *.so *.pdb *.ilk *.exp *.pch *.ipch *.class *.jar *.zip *.7z *.gz *.png *.jpg *.gif *.bmp *.ico *.pdf *.ttf *.woff *.mp3 *.mp4 *.wav

project_max_files

A project scan stops after this many files and says so (1000 to 10000000).

project_max_files = 1000000

search_workers

Project-wide search (C-x p g): the threads that read the files (1 to 16; 0 = from the number of processors), and the matches it lists before it stops and says so (1 to 1000000).

search_workers = 0
search_max_results = 10000

compilation_save_buffers

Builds (C-x p c, M-x compile): before a build starts, the file buffers with unsaved changes are asked about one by one (ask), all saved (all) or left as they are (none).

compilation_save_buffers = ask

compilation_scroll_output

The windows showing *compilation* follow its output until the first error appears (first-error), always (true) or not at all (false).

compilation_scroll_output = first-error

compilation_max_output_mb

The output kept in *compilation*, in MB (1 to 1024); past it one line says [output truncated] and the rest is read and dropped.

compilation_max_output_mb = 16

compilation_relative_paths

A location printed with an absolute path under the project root is shown with the path relative to the root (the location itself keeps the full path); false shows the line as printed.

compilation_relative_paths = true

max_cursors

Multiple cursors (C->, C-<, C-c C-<, C-S-c C-S-c, Ctrl+Shift+click): a command that would add more than this many stops there and says so (1 to 100000).

max_cursors = 10000

git_diff_max_lines

The git changes view (C-x g) runs git.exe from PATH, or the program set here, e.g. git_path = C:\Program Files\Git\cmd\git.exe A diff is cut after git_diff_max_lines lines (100 to 1000000) and the file list after git_status_max_files files (10 to 100000), each with a last line saying so; a git that prints nothing for git_timeout_ms (1000 to 600000) is stopped.

git_diff_max_lines = 20000
git_status_max_files = 5000
git_timeout_ms = 30000

ai_provider

C-c t opens a terminal in the file's directory; C-c a one in the project's root running an AI assistant's command line tool: claude, openai (codex) or custom (ai_command). ai_command, when set, is run instead for any provider, e.g. ai_command = claude --continue terminal: wt (Windows Terminal), cmd (the classic console) or auto (wt.exe when it is on PATH).

ai_provider = claude
terminal = auto

theme

The color theme: ronin (these colors), moonfly, oxide, vague or mellifluous, built in; or a theme file themes\<name>.conf in this file's folder (or in ronin.exe's), which replaces a built-in theme of the same name. A theme file holds a [theme] block (name, source, commit, license, author) and a [colors] section with the keys below; a key it leaves out keeps ronin's color or follows the key it derives from. Theme files are watched: a change applies at once. M-x set-theme switches for the session only.

theme = ronin
