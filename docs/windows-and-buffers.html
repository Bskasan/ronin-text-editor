Windows and buffers

Windows

The frame holds up to 8 windows, side by side or one above the other, each showing a buffer with its own point and scroll position; two windows can show the same buffer. A click selects a window; drag the line between two windows, or a mode line, to resize.

keyscommandwhat it does
C-x 2 C-x 3split-window-below split-window-rightsplit the selected window below / right
C-x oother-windowselect the next window
C-x 0 C-x 1delete-window delete-other-windowsdelete the selected window / every other one
C-x +balance-windowsmake the windows equal
C-x ^ C-x } C-x {enlarge-window enlarge-window-horizontally shrink-window-horizontallychange the selected window's size
C-M-v C-M-S-vscroll-other-window scroll-other-window-downscroll the next window forward / back
C-x 4 f C-x 4 bfind-file-other-window switch-to-buffer-other-windowa file / a buffer in another window
C-x 4 0kill-buffer-and-windowkill the buffer and delete its window

A command that shows a buffer in another window (C-x 4 b, C-x 4 f, C-h e) splits a single window side by side when the frame is at least split_width_threshold columns wide, otherwise one above the other. startup_windows set to 2 starts with two windows side by side.

Buffers and files

Every open file is a buffer; *scratch* has no file, and *Messages* (C-h e) keeps what the echo area said.

keyscommandwhat it does
C-x C-ffind-fileopen a file, with completion
C-x C-s C-x ssave-buffer save-some-bufferssave the buffer / the modified buffers, asking about each
C-x C-wwrite-filewrite the buffer to another file and visit that
C-x bswitch-to-bufferswitch the selected window to another buffer
C-x kkill-bufferkill a buffer, asking to save it if modified
C-x <left> C-x <right>previous-buffer next-bufferthe previous / next buffer of the buffer list
C-x C-csave-buffers-kill-terminalquit, asking about unsaved files

Files are UTF-8 or UTF-16 with a byte order mark; LF, CRLF and mixed line endings are kept byte for byte, and a save goes through a temporary file.

Files changed on disk

With auto_revert (the default), a buffer without unsaved changes whose file changed on disk is reloaded, when ronin is activated and at once for the buffers on screen. A buffer with unsaved changes is never touched, only flagged in the mode line. M-x revert-buffer reloads a buffer from its file by hand.

Crash recovery

When ronin itself crashes, it first writes its unsaved buffers to %LOCALAPPDATA%\ronin\recovery; the next start says so, and M-x recover-file recovers a file from its copy. It is a best effort: nothing is written when the process is ended from outside or the power fails.
