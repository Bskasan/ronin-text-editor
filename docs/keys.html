Keys and commands

Every command with what it does and its default keys, generated from ronin's command table and built-in configuration, so this page says what the program does. Keys are written as describe-key (C-h k) prints them: the notation is on First steps, how to change them under Configuration.

Each section below is a section of the configuration file. The keys of [keys minibuffer], [keys search-results], [keys compilation], [keys command-list], [keys git-changes] and [keys isearch] come first in their places; every other key falls through to [keys]. A command bound nowhere is run with M-x and its name.

[keys]

One binding per line: a key sequence, then the command. The last word on the line is the command and everything before it is the key sequence, so keys such as "=" need no quoting. The command "none" removes a binding. Later lines win: binding a sequence removes the bindings it conflicts with (binding C-x would remove every C-x ... binding), with a warning.

Key notation, as Emacs' kbd:

  C- Ctrl, M- Alt (Meta), S- Shift, combined in any order: C-M-<home>.
  A character: a  5  /  {  ;  and so on. SPC is the space bar.
  Named keys: RET TAB ESC DEL (Backspace) <delete> <insert> <home> <end> <prior> (Page Up)
  <next> (Page Down) <left> <right> <up> <down> <f1> ... <f24> <pause> <apps>.
  A sequence is up to 4 keys separated by spaces: C-x C-s.

Keys match by the character they type in the current keyboard layout: C-/ is Ctrl with whatever key types "/". Shift is part of the character for everything except letters, so Ctrl+Shift+/ on a US keyboard is C-? and letters keep it as a modifier: C-S-a. A key with Shift and no binding runs the binding it has without Shift. Plain characters can be bound too (they then stop inserting themselves); the second key of a sequence often is one (C-x o). Because '#' starts a comment, a lone "#" key cannot be bound (M-# can).

[keys minibuffer]

While the minibuffer reads something (M-x, C-x C-f, ...), these bindings come first; every other key falls through to [keys] above, so all editing commands work in it. C-g and ESC abort any prompt, including the y / n questions, whose other keys are taken as answers. RET takes the selected candidate (or the input when there is no list), C-j the input exactly as typed. TAB completes to the longest common part, then to the selection. Candidates match when every space-separated word of the input occurs in them, ignoring case.

[keys search-results]

In a results buffer (*search*, *occur*) these bindings come first. RET visits the match on its line in another window and selects it; n and p show the next and previous match in another window and stay in the results; g runs the search again; q closes the results window.

[keys command-list]

While the command list (C-S-p) is open these bindings come first. Typed characters and the line editing commands (C-a, C-e, C-f, C-b, M-f, M-b, DEL, C-d, C-k, M-DEL, C-w, M-w, C-y, M-y, C-/ ...) edit the filter; any other command is refused while the list is open. C-g, ESC or a click outside close it. A click selects a row, a double click runs it, the wheel scrolls.

[keys git-changes]

While the git changes view (C-x g) is open these bindings come first; any other command is refused. The movement keys select a file on the left (its diff is fetched once) or, after TAB, scroll the diff on the right; TAB goes back. RET visits the selected file at its first change, g runs git status again, C-g, ESC or a click outside close the view. The wheel scrolls the pane under the pointer.

[keys isearch]

While an isearch is active these bindings come first. Typed characters extend the search string; a key bound to any other command ends the search at the match and then runs that command. A search string without capital letters matches either case, one with a capital letter matches exactly (M-c switches). Repeating at the last match wraps around the buffer. RET and ESC end the search at the match and set the mark where it started; C-g goes back there (or, while the search is failing, first removes the part that is not found).
